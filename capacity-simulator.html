Where these numbers come from

the command for each field above, on a real cluster
Node capacity — the chip values, per node
$ oc get nodes -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.status.capacity.memory}{"\n"}{end}'
System + kube reserved + eviction — §1
$ oc get kubeletconfig -o yaml | grep -A5 systemReserved
DaemonSet requests per node — §2
$ oc get pods -A -o json | jq -r '.items[] | select(.metadata.ownerReferences[]?.kind=="DaemonSet") |
.spec.nodeName + " " + .spec.containers[].resources.requests.memory'
maxUnavailable — §3, from the pool's MachineConfigPool
$ oc get machineconfigpool worker -o jsonpath='{.spec.maxUnavailable}{"\n"}'
Sum of non-DaemonSet requests — the Workload card
$ oc get pods -A -o json | jq -r '.items[] | select(.metadata.ownerReferences[]?.kind!="DaemonSet") |
.spec.containers[].resources.requests.memory' # sum by hand, or the PromQL on the arithmetic page
Largest single pod's request — §4, bin-packing check
$ oc get pods -A -o json | jq -r '.items[].spec.containers[].resources.requests.memory' | sort -h | tail -1
HPA-managed requests, current/min/max replicas
$ oc get hpa -A -o custom-columns=NS:.metadata.namespace,NAME:.metadata.name,CUR:.status.currentReplicas,MIN:.spec.minReplicas,MAX:.spec.maxReplicas
PDB minAvailable floor
$ oc get pdb -A -o custom-columns=NS:.metadata.namespace,NAME:.metadata.name,MIN-AVAILABLE:.spec.minAvailable

Full derivation, worked example, and the fleet-wide PromQL version of these live in the arithmetic.

Models memory only — the same method applies to vCPU with its own reservation and request numbers. Nodes are assumed to already be Ready; this does not account for a node that is itself down in addition to the one being drained. See also the worked-example write-up.

This is a simplified model for illustration. Always consult the official Kubernetes documentation (and the OpenShift docs) to verify current features and behavior before relying on these numbers.
